# CLAUDE.md

This file provides guidance to Claude Code (claude.ai/code) when working with code in this repository.

## Commands

```pwsh
# Build
dotnet build

# Test (all)
dotnet test

# Test (single project)
dotnet test tests/AgentBattle.Poker.Mcp.Tests

# Run a battle (requires local Ollama)
dotnet run --project src/AgentBattle.BattleRunner -- battle run --config configs/poker-3p-ollama.yaml --agents-dir agents

# Live Razor Pages viewer
dotnet run --project src/AgentBattle.Web

# Regenerate static site data manifests
dotnet run --project src/AgentBattle.SiteGenerator -- --battles-dir battles --agents-dir agents --out-dir static-site

# Serve static site locally
python -m http.server -d static-site 8000
```

## Architecture

AgentBattle runs poker matches between LLM agents. Each battle is recorded as an append-only JSONL file in `battles/`, then replayed through either the live Razor Pages web app or the static GitHub Pages site.

### Data flow

```
agents/*.yaml + configs/*.yaml
       ↓
BattleRunner (CLI) — spawns subprocess →
       AgentBattle.Poker.Mcp (MCP server, game engine)
       ↑ MCP stdio transport ↑
BattleOrchestrator (turn loop, LLM calls)
       ↓
battles/<timestamp>-<id>.jsonl  ←  JsonlEventSink
       ↓
SiteGenerator → static-site/data/*.json + copies .jsonl files
       ↓
GitHub Pages deploy (triggered by push to main)
```

### Projects

| Project | Type | Role |
|---|---|---|
| `AgentBattle.Domain` | Library | Poker models, BattleEvent schema, JSON serialization |
| `AgentBattle.Poker.Mcp` | Console | MCP server; runs as subprocess, owns all poker rules |
| `AgentBattle.Orchestrator` | Library | Turn loop, agent HTTP clients, prompt building, action parsing |
| `AgentBattle.BattleRunner` | Console | CLI entry point; wires config → orchestrator → MCP server |
| `AgentBattle.Web` | ASP.NET Razor Pages | Live battle viewer; reads battles/ and agents/ from disk |
| `AgentBattle.Web.Core` | Library | BattleArchive, AgentRegistry, StatsAggregator — shared web services |
| `AgentBattle.SiteGenerator` | Console | Generates static-site/data manifests; called by CI |

### Key design points

**MCP isolation** — Poker rules live entirely in `AgentBattle.Poker.Mcp`. `BattleOrchestrator` communicates with it only through MCP tools over stdio. Swapping the game engine means replacing this subprocess.

**OpenAI-compatible agent client** — `OpenAiCompatibleAgent` works with Ollama, OpenAI, Anthropic (via proxy), or any OpenAI-compatible endpoint. Agent configs in `agents/*.yaml` specify `endpoint`, `model`, and `apiKeyEnvVar`.

**JSONL as audit log** — Every game event (deal, thought, action, showdown, chip update) is a `BattleEvent` record appended to one file per battle. `BattleEventJsonOptions` holds the polymorphic JSON discriminator config.

**Static site — no build step** — `static-site/` is plain HTML, Alpine.js, and ES modules. No bundler, no TypeScript. `data/*.json` manifests are generated by `SiteGenerator` at CI time and committed/deployed.

**Central package management** — All NuGet versions are in `Directory.Packages.props`. Add versions there; reference without version in `.csproj` files.

### Patterns

- Polymorphic `BattleEvent` records use a `$type` discriminator. New event types go in `AgentBattle.Domain/Battles/`.
- Test projects mirror the project they test: `tests/AgentBattle.Poker.Mcp.Tests` tests `src/AgentBattle.Poker.Mcp`.
- `AgentBattle.Web.Core` is shared between the Razor Pages app and test projects; keep it free of ASP.NET dependencies.
- API keys are always environment variables; never hardcoded or committed.
