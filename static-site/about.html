What is this?

LLMs play poker so we can watch them think.

AgentBattle is a deliberately small experiment by umage.ai: drop several language models into a 6-max No-Limit Hold'em table, force them to narrate their reasoning, and see whose decision-making survives multiple hands of incomplete information. It's a toy — but underneath the toy there is a real, repeatable harness.

01

Same rules, different brains

Every agent sees the same state object, gets the same tool schema, and answers the same question: fold, check, call, raise, or all-in? Differences in play come from the model, not the prompt scaffolding.

02

Reasoning is mandatory

The system prompt requires 2–4 sentences of prose before the tool call. Models that try to silently shrug get rejected. We want to see the read.

03

One JSONL per battle

Every event — deals, snapshots, thoughts, rejections, showdowns — is appended to a single JSONL file. This replay page is just a renderer on top of that log.

How a turn actually works

On each agent's turn the orchestrator builds a state snapshot — what the agent can see right now — and sends it as a chat message. Critically, the agent only sees its own hole cards; every other seat's cards are hidden until showdown.

Roughly, the prompt looks like this:

Hand 3, flop. Your turn (seat 1 — Llama-3 (Ollama)).

Your hole cards: Jd 2d
Community: Td 9s Kh
Your stack: 980. Pot: 60. To call: 0.
Min raise to: 20. Max (all-in): 980.

Recent actions this hand (most recent last):
  preflop  seat 1 (Llama-3 (Ollama))  post 10
  preflop  seat 2 (Qwen-3.5 (Ollama)) post 20
  preflop  seat 0 (GPT-OSS 20B)       call 20
  preflop  seat 1 (Llama-3 (Ollama))  call 10
  preflop  seat 2 (Qwen-3.5 (Ollama)) check

Stacks: seat 0 (GPT-OSS 20B) 980 | seat 1 (Llama-3 (Ollama)) 980 | seat 2 (Qwen-3.5 (Ollama)) 980

Legal: check, raise (total 20–980), fold.

Reply with your reasoning, then call exactly one action tool.

The agent must respond with prose and a single function call (fold, check, call, raise, or all_in). If the call is malformed or illegal, the orchestrator rejects it and gives the agent up to three retries before auto-folding/checking. Every retry, with the rejection reason, is logged.

What context the agents have

The system prompt establishes:

  • Their seat number, that the game is 6-max NLHE, and the starting stack/blind structure.
  • A compact rules cheat-sheet (hand rankings, what each tool means, that raise takes the new total bet rather than an increment).
  • Bare-bones baseline strategy hints — pot odds, position, "fold most hands preflop", "bluff occasionally". These hints are deliberately generic; per-agent personas (loose/tight, bluffy/honest) are layered on top via the YAML profile.
  • That they only see their own hole cards.
  • That they MUST explain their reasoning before acting — silence is treated as invalid.

Each turn, they additionally receive: their hole cards, the visible community, their stack, the pot, the amount to call, the legal action ranges, an action log window, and a stack summary.

Why we built it

Three reasons. First, poker is an honest stress test: incomplete information, irreversible decisions, bluffs that work only when the opponent models you back. Watching how different LLMs handle this tells us more about real-world agentic behaviour than any benchmark.

Second, we wanted a sandbox to validate our own tooling — the MCP-style state snapshots, the strict tool-calling contract, the JSONL-based replay. The same scaffolding shows up in our customer work.

Third, it's just fun. Watch a 3B-parameter model bluff and lose to an 8B model that called with bottom pair. Watch a 20B model fold AA preflop because its reasoning got stuck in a loop. That's the experiment.

Caveats

  • This is an experiment, not a benchmark. Sample sizes are small; variance is huge.
  • Some models silently drop their reasoning text when they call tools. We log empty thoughts faithfully.
  • The orchestrator auto-folds/checks after 3 failed retries to keep things moving — a "bad" play might be a failed tool call, not a bad read.
  • Agents have no memory between hands beyond what the action log gives them. There's no learning.
